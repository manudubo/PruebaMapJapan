# Production hardening for internet exposure

**Date:** 2026-10-07
**Base:** `origin/claude/focused-lovelace-cryssy` @ `eb62969`, merged again with its later head (A11Y/LCP, real-auth QA).
**Branch:** worktree branch, not pushed.
**Target:** frontend on GitHub Pages (`https://manudubo.github.io/PruebaMapJapan/`); backend (Node), Keycloak and
Postgres on a home server reachable from the internet. Stage 1 is **single-host mode**: one Tailscale Funnel host
name with path routing (`https://<machine>.<tailnet>.ts.net/api`, `…/auth` with `KC_HTTP_RELATIVE_PATH=/auth`),
Funnel → Caddy → app. Split hosts (`api.<domain>`, `auth.<domain>`) also work. The Docker/compose kit and
`backend/src/server.ts` belong to the self-host work stream and are not in this branch.

### Also found (not fixed, outside scope)

- **Login from a URL with a query string fails.** `AuthGuard`/`client.ts` call `login(window.location.href)`. For `trip-edit.html?tripId=12` Keycloak answers 400 "Invalid redirect_uri" (verified live), because redirect URIs are exact and `trip-edit.html` was never listed. The secure fix is in the frontend: redirect to a listed page and restore the target from `sessionStorage`. Adding `*` wildcards would weaken the allow-list. Logout to `window.location.origin` (no trailing slash) is also rejected; `Navbar` passes `index.html`, which works.
- `tests/e2e/idp-flow.spec.ts` passkey tests need *something* listening on `localhost:5173`, otherwise the post-login navigation to `chrome-error://` interrupts the next `goto`. They passed with a stub server.

## Environment contract (backend)

| Variable | Default | Notes |
|---|---|---|
| `ALLOWED_ORIGINS` | Pages origin from `config/deploy-defaults.json` | exact origins, comma-separated; empty = none |
| `TRUSTED_PROXY_HOPS` | `0` | Funnel → Caddy → app: `2`; Workers: `1` with `CLIENT_IP_HEADER=cf-connecting-ip` |
| `CLIENT_IP_HEADER` | `x-forwarded-for` | `x-real-ip`, `cf-connecting-ip`; read only when hops > 0 |
| `KEYCLOAK_URL` | — | may include `/auth` |
| `KEYCLOAK_ISSUER` | `${KEYCLOAK_URL}/realms/${KEYCLOAK_REALM}` | override when the public issuer differs |
| `KEYCLOAK_JWKS_URL` | derived from `KEYCLOAK_URL` | internal URL allowed |
| `ALLOWED_AZP` | `VALID_AUDIENCES` | clients whose access tokens are accepted |
| `EMAIL_PROVIDER` | inferred | `resend` or `smtp` |
| `EMAIL_FROM` / `SMTP_FROM` | Resend: legacy default; SMTP: required | `addr` or `Name <addr>` |
| `SMTP_HOST`, `SMTP_PORT` (587), `SMTP_SECURE` (`starttls`), `SMTP_USER`, `SMTP_PASS` | | `none` only in development; user and pass together |
| `NOMINATIM_CONTACT` | dev: placeholder | required outside development for `/api/geocode` |
| `NOMINATIM_URL` | public instance | https outside development |

**Node server contract** (for `backend/src/server.ts`): pass the `@hono/node-server` `incoming` object in the
bindings (`fetch: (req, nodeEnv) => app.fetch(req, { ...bindings, ...nodeEnv })`). The peer address comes from
`c.env.incoming.socket.remoteAddress`; without it every client shares the `ip:unknown` bucket. Forward the variables
above from `process.env`, and call `assertEmailConfig(env)` and `setMinLogLevel(process.env.LOG_LEVEL)` at startup.

## Not validated here

- The real Tailscale Funnel → Caddy → backend chain (`TRUSTED_PROXY_HOPS=2`, `X-Forwarded-Proto`). It is covered by unit/adversarial tests with simulated headers only.
- Real Gmail delivery (needs the owner's account and app password). SMTP was exercised against a local server implementing STARTTLS/AUTH.
- Firefox/WebKit runs of the new Keycloak spec (Chromium only).
- Cloudflare Workers runtime behaviour of the memory rate limiter. SMTP on Workers is not supported (`node:net`); use Resend there.
- The full E2E suite with frontend + backend + Mailpit (global-setup login); only the IdP specs were run.
