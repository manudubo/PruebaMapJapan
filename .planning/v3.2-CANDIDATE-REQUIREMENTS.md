## Cluster 0 — Already addressed by v3.1 (do not re-plan)

codex-review.md's headline risk was "the E2E harness doesn't reliably prove auth/session/passkey behavior." That's exactly what v3.1 Phases 15–19 did:

- `loginViaKcForm` shared helper (Phase 17) replaces the four independent, fragile KC-navigation implementations codex's finding #4 flagged.
- `sessionStorage`-token replay assumption (codex #4, #12, #18; ANALISIS B-08) — the underlying test *behavior* was fixed in Phase 17; the stale doc comment (ANALISIS B-08, codex #18) is still open, see BUG-06 below.
- Firefox/WebKit instability (codex #5) — directly addressed by Phase 19's D-03 storageState parity fix, the session-test@local dedicated-user fix for cross-contamination, and the passkeyCampaign cookie-preseed fix (Phase 19 plan 02).
- `session-management.spec.ts` selector/flow fragility (codex #12) — Phase 19 (SESSION-01), closed 2026-07-23. Live-verified 7/7 on chromium (ANALISIS-REPO 7th pass) and full suite green (this session).
- WebAuthn required-action race (codex implicit in #1 test failures) — Phase 17/18/19 all hardened around this (`hitRequiredAction`, Case B guards).
- **KC-C** (ANALISIS 7th pass) — Keycloak's "some clients have not been logged out" warning investigated and closed as benign (standard message for a public SPA client with no backchannel logout URL); logout does destroy the KC server session (verified via Admin API assertion).

**Do not** re-open these as v3.2 work.
