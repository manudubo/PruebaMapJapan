    ```markdown
    **Config:** Post-SETUP-02 (passkeys scoped to chromium-passkeys)

    |------|-----------|-----------------|--------------|-----------------|
    | ... | ... | ... | ... | ... |

    ```

    Status value rules — apply to each spec row:
    - `Pass` — all attempts green across all projects
    - `Fail` — failed on all retries (attempt 0 and attempt 1 both failed)
    - `Flaky` — failed attempt 0, passed attempt 1 (indicates non-deterministic behavior)
    - `Skip(SKIP_REAL_AUTH)` — test skipped due to SKIP_REAL_AUTH env guard
    - `Skip(test.skip)` — test skipped by explicit test.skip() call in spec

    Failure mode categories (use exactly these values):
    - `config-bug` — testIgnore/testMatch misconfiguration (should not appear post-SETUP-02)
    - `contract-mismatch` — spec sends request that does not match backend route contract
    - `missing-fixture` — spec expects data (trip, user, etc.) that does not exist in DB
    - `env` — KC/Mailpit/Postgres not running or timing issue
    - `flaky` — passed on retry; root cause unclear
    - `unknown` — multiple hypotheses; needs deeper investigation

    Suggested Phase column values: Phase 16, Phase 17, Phase 18, Phase 19, or N/A.

    Pre-existing baseline to diff against (from .planning/research/SUMMARY.md):
    - passkeys.spec.ts under firefox and webkit: resolved by SETUP-02 → must NOT appear
      as a failure row in 15-TRIAGE.md
    - otp.spec.ts tests 1–3: expected Fail, contract-mismatch → Phase 17
    - public-sharing.spec.ts: expected Fail, missing-fixture → Phase 16
    - idp-theme.spec.ts: unconfirmed — classify from live output
    - session-management.spec.ts: unconfirmed — classify from live output

    Any failing spec NOT in the above baseline is newly introduced. Flag it in the
    Notes section with: "NEWLY INTRODUCED: [spec] — not in v3.0 stale list."

    If a spec appears flaky, note in Notes: "FLAKY: [spec] — re-run in isolation to
    confirm (parallelism artifact possible; per RESEARCH pitfall 4)."

    Trace files live at tests/test-results/ — do NOT commit them. Note the path in the
    header only.

    After writing the file, commit it:
    `git add .planning/milestones/v3.1-phases/15-triage-config/15-TRIAGE.md`
