## Milestone Summary

**Key Decisions:**

- Dedicated `session-test@local` KC user (Terraform-provisioned) instead of sharing `e2e-test@local` — eliminates cross-spec session cross-contamination on `logoutUser()` calls. Standing preference going forward: every E2E spec should ideally have its own dedicated user.
- `waitForLoadState('networkidle')` removed wherever used as a wait condition — Vite's HMR WebSocket keeps the page perpetually non-idle, causing indefinite hangs (worst on webkit). Replaced with locator-based waits.
- passkeyCampaign per-device cookie (`pnk_<userId>`) pre-seeded via `context.addCookies()` before login — reliably suppresses the `webauthn-register-passwordless` required-action redirect on chromium/firefox, but not webkit (accepted as environment constraint after repeated isolated reproduction).
- `test.fixme(condition, reason)` used consistently for genuine environment constraints, never as a silent skip — every deferral carries a documented rationale traceable to a specific root cause.
- 69 local commits that had gone unpushed for an extended period were backed up to `origin/backup/2026-07-22` rather than merged straight to `main`, because the deploy workflows have no CI gate and the backend currently fails `wrangler deploy --dry-run` (tracked as v3.2 candidate INFRA-03).

**Issues Resolved:**

- Fresh, authoritative full-suite triage replaced a stale, several-commits-old failure list.
- Cross-browser passkey config bug (spec running under firefox/webkit projects it was never meant for).
- OTP spec/route contract mismatch (missing auth headers, single-shot polling causing SMTP-lag false failures).
- Stale Spanish-locale assertion in `public-sharing.spec.ts` (removed in Phase 5's i18n pass but never updated in the test).
- Passkey campaign hijacking subsequent tests via leftover `webauthn-register-passwordless` required actions.
- Real production bug: `tripDetail.ts` never set `#trip-title` for a trip with zero destinations.

**Issues Deferred:**

- webkit-only session-restoration limitations (`auth.spec.ts` real-session, `public-sharing.spec.ts`, 2 tests in `session-management.spec.ts`) — all traced to the same passkeyCampaign/storageState root cause, documented as accepted `test.fixme` deferrals.
- `trip-edit-integration.spec.ts` (5 tests, all browsers) — backend integration not implemented in v3.1, pre-written for a future phase.
- `new-user-trip-creation.spec.ts` webkit — pre-existing environment constraint from Phase 19-01.

**Technical Debt Incurred:**

- None new. Existing debt (backend build broken, unused Keycloak admin permission, dependency vulnerabilities, and ~80 other findings) captured comprehensively in `.planning/v3.2-CANDIDATE-REQUIREMENTS.md` for the next milestone.
