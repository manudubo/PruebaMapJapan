**Step 2 — Rewrite renderTripCard:**

Change signature from `function renderTripCard(trip: ApiTrip): string` to `function renderTripCard(trip: ApiTrip): HTMLElement`.

Build the card DOM imperatively following the createElement → className → textContent → appendChild pattern from `renderUserGreeting` (lines 75-80) and `buildLegendItem` in tripDetail.ts.

The card has these elements (from the current template, PATTERNS.md lines 43-48):
- Outer: `div.trip-card` with `aria-label` = trip name
- Cover image area: `div.trip-card-cover` — `setStyle(coverEl, 'background-image', \`url('${trip.cover_image_url}')\`)` (per D-03)
- Title: `h3.trip-card-title` — `setText(h3, trip.name)`
- Description: `p.trip-card-description` — `setText(p, trip.description ?? '')`
- Any links or click handlers: use `setAttribute('href', ...)` or `addEventListener` — not innerHTML

For the `aria-label` on the outer card: `card.setAttribute('aria-label', trip.name)` — safe attribute assignment.

Return `card` at the end.

**Step 3 — Fix grid population (line 72 approx):**

Replace:
```typescript
grid.innerHTML = trips.map(t => renderTripCard(t)).join('');
```

With:
```typescript
grid.innerHTML = '';
trips.forEach(t => grid.appendChild(renderTripCard(t)));
```

The `grid.innerHTML = ''` clear is safe (empty string, no user data).

**Step 4 — Fix empty state (lines 63-70 approx):**

`grid.innerHTML = \`<p ...>No tienes viajes.</p>\`` or similar static markup.

const msg = document.createElement('p');

(Match exact class name and text from the current template.)

Replace: `setText(grid, (err as Error).message)` OR create a `<p>` element and setText. Use existing class names from the template.

Note: after changing `renderTripCard` return type, TypeScript will type-check all call sites. The `.join('')` + `innerHTML` call site in Step 3 must be updated or the build fails with a type error.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API response → trip card grid | Trip list data (names, descriptions, cover image URLs) enters DOM through the card renderer |
| caught Error → DOM | Error.message from fetch failures enters the error display element |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | renderTripCard trip.name injection | mitigate | setText(h3, trip.name) — textContent prevents HTML interpretation; aria-label via setAttribute |
| T-08-02 | Tampering | renderTripCard trip.description injection | mitigate | setText(p, trip.description) — textContent, no HTML interpretation |
| T-08-03 | Tampering | cover_image_url CSS injection | mitigate | setStyle(coverEl, 'background-image', url(...)) — CSS parser sandboxes; expression() attack requires IE6 (D-03 accepted) |
| T-08-04 | Tampering | error message injection | mitigate | setText used for error display — Error.message text rendered as plain text, not HTML |
</threat_model>
