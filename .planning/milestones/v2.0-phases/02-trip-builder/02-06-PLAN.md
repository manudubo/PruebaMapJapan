Create `frontend/src/pages/trip-edit/hotels.ts`. This module is called by destinations.ts for each destination — it creates and manages the hotel UI for a single destination.

**Function signature:**
```typescript
export function renderHotelSection(
  container: HTMLElement,
  dest: ApiDestination,
  tripId: string,
): void
```

The module must:

1. **Render hotel display** inside `container`:
   - If `dest.hotel` is null or undefined: show `.empty-state` paragraph with text "Sin hotel asignado." and an "Agregar hotel" button (`.btn btn-secondary`)
   - If `dest.hotel` exists: show hotel name (via `setText`), URL as plain text (`setText` — NOT as `<a href>` — security: prevents javascript: URL injection), check-in/out dates, and "Editar" + "Eliminar" buttons

2. **Hotel modal** (created dynamically and appended to document.body, or reused per-destination):
   Modal form fields per D-03:
   - Name (required, maxlength 255)
   - URL (`<input type="url">` with placeholder "https://…", optional)
   - Check-in date (`<input type="date">`, optional)
   - Check-out date (`<input type="date">`, optional)
   - Geocoder widget for optional coordinates (same pattern as destinations.ts geocoder widget: text input + "Buscar lugar" button + results div + hidden lat/lng inputs)
   - Error display: `.error-msg` paragraph
   - Actions: "Cancelar" + "Guardar" buttons

   Modal titles:
   - Add mode: "Agregar hotel"
   - Edit mode (hotel already exists): "Editar hotel"

3. **Geocoder widget** inside hotel modal: same implementation pattern as destinations.ts — `isGoogleMapsUrl` check → `extractCoordsFromGoogleMapsUrl` for Maps URLs; `searchNominatim` for text queries. All result text via `textContent`/`setText`.

4. **Form submission** (upsert — both add and edit use PUT):
   ```typescript
   await upsertHotel(tripId, dest.id, {
     name,
     url: url || null,         // empty string becomes null
     check_in_date: checkIn || null,
     check_out_date: checkOut || null,
     lat: latValue || null,
     lng: lngValue || null,
   });
   ```
   On success: re-render hotel display inside `container` (update local `dest.hotel` reference or re-call renderHotelSection with updated data).
   On error: show `.error-msg` "No se pudo guardar. Verificá tu conexión e intentá de nuevo."

5. **Delete flow** using `#confirm-overlay` (shared overlay already in trip-edit.html):
   - "Eliminar" click: set `#confirm-title` = "¿Eliminar hotel?", `#confirm-msg` = "Esta acción no se puede deshacer."
   - `#confirm-delete-btn` click: call `deleteHotel(tripId, dest.id)`; on success re-render as empty state
   - `#confirm-cancel-btn` / Escape: hide overlay
   - Error state: show `#confirm-error` inside overlay

6. **Critical: hotel.url rendered as plain text** — NEVER render url as an anchor href. This prevents javascript: URL injection:
   ```typescript
   // CORRECT:
   const urlEl = document.createElement('p');
   setText(urlEl, hotel.url ?? '');
   container.appendChild(urlEl);

   // WRONG (do not do this):
   // const a = document.createElement('a');
   // a.href = hotel.url; // XSS via javascript:... URL
   ```

7. **Null-check hotel everywhere** — `dest.hotel` is typed as `ApiHotel | undefined`. Never access `.name` or `.url` without checking.

8. **Security invariants**: No innerHTML with user-controlled strings. All text from API via `setText` or `.textContent`.
