## Summary

Phase 2 delivers the full trip edit UI as a new `trip-edit.html` MPA page. The backend REST API is almost entirely complete — all CRUD endpoints for trips, destinations, days, activities, and hotel upsert exist. Two significant backend gaps were found during research: no DELETE endpoint for days and no DELETE endpoint for the hotel resource. These must be added as part of this phase.

The frontend `client.ts` API client is similarly incomplete: it is missing `updateDay`, `deleteDay`, `upsertHotel`, `deleteHotel`, and `reorderActivities` functions. The UI can be implemented as a `trip-edit.ts` module following the structural template of `tripDetail.ts` (URL param extraction, auth init, API fetch, DOM rendering with `setText`/`setStyle`). The `.overlay`/`.modal` pattern from `dashboard.html` is fully reusable.

The Drizzle migration is a single `ALTER TABLE` adding two nullable columns (`activities.time` and `hotels.url`), generated by `drizzle-kit generate` and applied via `drizzle-kit migrate`. The geocoder (TRIP-07) calls Nominatim directly from the browser — 1 request/second limit enforced by the button-click UX, and the `User-Agent` header must identify the app. Google Maps URL parsing uses a regex on the `@lat,lng` fragment.

**Primary recommendation:** Implement bottom-up — migration first, schema+validation updates second, missing backend endpoints third, client.ts additions fourth, then the trip-edit.html/ts frontend.

### Pattern 4: Geocoder Widget — Nominatim

```typescript
// Source: Nominatim API docs (nominatim.org/release-docs/latest/api/Search/)
// [CITED: https://nominatim.org/release-docs/latest/api/Search/]
async function searchNominatim(query: string): Promise<NominatimResult[]> {
  const url = new URL('https://nominatim.openstreetmap.org/search');
  url.searchParams.set('q', query);
  url.searchParams.set('format', 'json');
  url.searchParams.set('limit', '5');

  const res = await fetch(url.toString(), {
    headers: {
      'User-Agent': 'PruebaMapJapan/1.0 (https://github.com/user/PruebaMapJapan)',
      'Accept-Language': 'es,en',
    },
  });
  return res.json() as Promise<NominatimResult[]>;
}

interface NominatimResult {
  lat: string;   // "35.6894875"
  lon: string;   // "139.6917064"
  display_name: string;
}
```

### Pattern 5: Google Maps URL Coordinate Extraction

```typescript
// Source: verified against Google Maps URL structure examples
// [CITED: https://gotoapplemaps.com/guides/google-maps-url-formats-explained/]
function extractCoordsFromGoogleMapsUrl(url: string): { lat: string; lng: string } | null {
  // Handles: /maps/place/Name/@lat,lng,zoom and /maps/@lat,lng,zoom
  const atMatch = url.match(/@(-?\d+\.\d+),(-?\d+\.\d+)/);
  if (atMatch) return { lat: atMatch[1], lng: atMatch[2] };

  // Handles: ?q=lat,lng
  const qMatch = url.match(/[?&]q=(-?\d+\.\d+),(-?\d+\.\d+)/);
  if (qMatch) return { lat: qMatch[1], lng: qMatch[2] };

  // Handles: !3d<lat>!4d<lng> (embedded in data URLs)
  const dataMatch = url.match(/!3d(-?\d+\.\d+)!4d(-?\d+\.\d+)/);
  if (dataMatch) return { lat: dataMatch[1], lng: dataMatch[2] };

  return null;
}

// In geocoder widget: detect if input looks like a Maps URL
function isGoogleMapsUrl(input: string): boolean {
  return input.includes('google.com/maps') || input.includes('maps.google.com') || input.includes('goo.gl/maps');
}
```

### Anti-Patterns to Avoid

- **Raw `innerHTML` for user content:** All text mutations must use `setText(el, text)` from `dom.ts`. This is a Phase 1 security invariant. Never use `el.innerHTML = userValue`.
- **Storing `--marker-N` as color_hex:** The DB and Zod both expect a 6-digit hex string. Resolve via `COLOR_MAP` before API call.
- **Nominatim on every keystroke:** Policy forbids autocomplete. Only call on explicit "Buscar lugar" button click.
- **Missing `User-Agent` header on Nominatim requests:** Stock fetch without a User-Agent header violates the usage policy and will result in 403 errors.
- **Default export on utility modules:** Phase 1 established named exports only. No `export default` on utility modules.
- **`document.getElementById` without null check:** All DOM lookups in TypeScript must be null-checked or use assertion patterns consistent with existing code.

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| SQL ALTER TABLE | Custom migration SQL | `drizzle-kit generate` + `drizzle-kit migrate` | Handles dialect differences, tracks migration state in `drizzle` table |

## Common Pitfalls

### Pitfall 1: color_hex DB/Zod Mismatch with CSS Variable Swatches

**What goes wrong:** Developer stores `"--marker-1"` in `color_hex` field. Zod schema has `regex(/^#[0-9A-Fa-f]{6}$/)` — the PATCH/POST request fails with 422 validation error.
**Why it happens:** UI-SPEC defines swatch `data-color="--marker-N"` for styling, but DB expects resolved hex.
**How to avoid:** Use the static `COLOR_MAP` lookup at form submission time. Pre-populate the reverse lookup when loading existing day data.
**Warning signs:** 422 errors from days endpoints; color swatches not highlighted when editing an existing day.

### Pitfall 2: Nominatim `User-Agent` Missing

**What goes wrong:** Browser's default `fetch` sends stock User-Agent. Nominatim returns HTTP 403.
**Why it happens:** OSM usage policy requires an identifying User-Agent [CITED: https://operations.osmfoundation.org/policies/nominatim/].
**How to avoid:** Always include `headers: { 'User-Agent': 'PruebaMapJapan/1.0 ...' }` in Nominatim fetch calls.
**Warning signs:** 403 responses in the network tab when clicking "Buscar lugar".

### Pitfall 3: Missing DELETE Endpoints at Runtime

**What goes wrong:** "Eliminar día" and "Eliminar hotel" buttons call client.ts functions that call non-existent backend routes → 404.
**Why it happens:** DB query helpers exist but routes were never registered in `trips.ts` (see Backend Gaps above).
**How to avoid:** Add both DELETE routes to `trips.ts` as a Wave 0 backend task, before any frontend delete UI is implemented.
**Warning signs:** 404 from `DELETE /api/trips/.../days/:dayId` in network tab.

### Pitfall 4: Serial Entity Creation With No Rollback

**What goes wrong:** User creates a destination, then the hotel creation fails. Destination exists but has no hotel — inconsistent state with no recovery UI.
**Why it happens:** STATE.md documents this explicitly: "Serial nested entity creation has no rollback."
**How to avoid:** Each entity is saved independently (separate forms/modals). Don't chain entity creation in a single transaction from the frontend. Show inline `.error-msg` per form; let user retry.
**Warning signs:** Partial state visible on page refresh.

### Pitfall 5: Destination Hotel Is Optional — Must Null-Check

**What goes wrong:** Frontend code assumes `destination.hotel` is always present and tries to render it unconditionally → TypeError at runtime.
**Why it happens:** `getTripById` uses Drizzle `with: { hotel: true }` which returns the hotel object when it exists and `null`/`undefined` when no hotel has been created for that destination [VERIFIED: reading `backend/src/db/queries/trips.ts`]. `ApiHotel` is typed as optional (`hotel?: ApiHotel`) in `types/index.ts`.
**How to avoid:** Always null-check `destination.hotel` before rendering hotel section. Show "Sin hotel asignado." empty state per UI-SPEC copywriting when `destination.hotel` is absent.
**Warning signs:** TypeError on page load for any destination that has no hotel yet.

### Pitfall 6: Reorder PATCH Uses `POST .../activities/reorder` (Not PATCH)

**What goes wrong:** Client sends PATCH to the reorder route → 405 Method Not Allowed.
**Why it happens:** The reorder endpoint uses `tripsRoute.post(...)` not `.patch()` [VERIFIED in trips.ts line 788].
**How to avoid:** `reorderActivities` client function must use `method: 'POST'`.

### Pitfall 7: "Generar todos los días" Without Smart Merge

**What goes wrong:** User clicks "Generar todos los días" a second time — all existing days are recreated as duplicates.
**Why it happens:** Destructive regeneration without checking existing dates.
**How to avoid:** Before creating each day: check the current loaded day list for that destination. If a day with that `date` already exists, skip it. Only create new dates in the gap.

### Pitfall 8: `is_optional` on Activities

**What goes wrong:** Activity modal (D-03 scope: "name, time, notes, optional geocoder") tries to send `is_optional` — field is not in the modal spec.
**Why it happens:** The word "optional" in D-03 refers to the geocoder field being optional, not an `is_optional` boolean.
**How to avoid:** Activity create/edit forms do NOT include `is_optional`. Default to `false` on all creates from this UI. The field exists in the schema for legacy data only.

### Pitfall 9: Drizzle `meta/` Snapshot Directory Absent

**What goes wrong:** Running `npm run db:generate` fails or generates a migration that attempts to recreate existing tables rather than adding only the two new columns.
**Why it happens:** `backend/src/db/migrations/` contains only `0000_initial.sql` — no `meta/` subdirectory was found [VERIFIED: listing migrations directory]. The `meta/` directory holds drizzle-kit's snapshot of the current schema state. Without it, drizzle-kit cannot diff against the previous state and may behave incorrectly.
**How to avoid:** Two safe options: (1) Hand-write `0001_add_hotel_url_activity_time.sql` as two `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` statements and skip `db:generate` entirely — safest when `meta/` is absent. (2) Run `drizzle-kit introspect` first (reads the live DB, creates `meta/` and a schema snapshot), then run `db:generate` — drizzle-kit can now diff against the snapshot and will emit only the two new `ALTER TABLE` statements. Either way, inspect the generated SQL before running `db:migrate` to confirm it contains no `CREATE TABLE` statements.
**Warning signs:** Generated migration SQL contains `CREATE TABLE` statements for tables that already exist; `db:migrate` errors with "table already exists".

## Geocoder: TRIP-07 Details

[VERIFIED: nominatim.org official docs + OSM Foundation usage policy]

### Nominatim Search

- **Endpoint:** `GET https://nominatim.openstreetmap.org/search`
- **Parameters:** `q` (free-form query), `format=json`, `limit=5`
- **Required header:** `User-Agent: PruebaMapJapan/1.0 (contact@example.com)` — stock User-Agent returns 403
- **Response fields:** `lat` (string), `lon` (string), `display_name` (string)
- **Rate limit:** 1 request/second absolute maximum [CITED: https://operations.osmfoundation.org/policies/nominatim/]
- **Autocomplete forbidden:** Only trigger on explicit button click, never on keypress
- **Attribution:** OSM data must be attributed (already handled by Leaflet tiles elsewhere)

### Google Maps URL Parsing

[CITED: https://developers.google.com/maps/documentation/urls/get-started]

| URL Pattern | Regex | Example |
|------------|-------|---------|
| Place URL with @lat,lng | `/@(-?\d+\.\d+),(-?\d+\.\d+)/` | `maps/place/Name/@35.6894,139.6917,17z` |
| Query URL ?q=lat,lng | `/[?&]q=(-?\d+\.\d+),(-?\d+\.\d+)/` | `?q=35.6894,139.6917` |
| Embedded data URL | `/!3d(-?\d+\.\d+)!4d(-?\d+\.\d+)/` | `!3d35.6894875!4d139.6917064` |

Detection: check if input contains `google.com/maps` or `goo.gl/maps` before applying regex (falls back to Nominatim search otherwise).

### UX Flow (per UI-SPEC)

1. User types query OR pastes Google Maps URL
2. User clicks "Buscar lugar" button
3. Button → "Buscando…" + disabled state
4. Results list appears with display names (Nominatim) or "Encontrado" (Maps URL parse)
5. User clicks result → lat/lng populated in hidden fields, results hidden
6. No results: "Sin resultados. Probá con otra búsqueda."
7. Error: `.error-msg` below results

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| XSS via user-controlled strings in DOM | Spoofing/Tampering | `setText(el, value)` — never `innerHTML` with user content (Phase 1 invariant) |
| IDOR — editing another user's trip | Elevation of Privilege | All routes use `resolveDestination/resolveDay/resolveActivity` — verify trip ownership before mutation |
| Nominatim SSRF | Tampering | Not applicable — Nominatim called client-side from browser, not via backend proxy |
| Zod bypass via extra fields | Tampering | Zod `.strip()` (default) on all schemas — unknown fields discarded |
| Hotel URL stored as-is | Tampering | `z.string().url()` validates on backend; frontend renders as plain text (not as `<a href>` in edit context) |
