Two weights only: 400 (body, label, caption, meta text, inline inputs) and 600 (headings, display/page title, badge uppercase labels).

- Inline error text: 14px / 400.

## Component Inventory

New components introduced in this phase. All must follow existing naming conventions (BEM-adjacent, kebab-case class names) and the established glass-panel / card visual language.

### trip-edit page layout

- Single scrolling page (`trip-edit.html`).
- Page header: `.dashboard-header` pattern — trip name (h1, focal point, `clamp(20px,4vw,28px)`, weight 600) + action buttons row. Focal point: trip name h1 is the primary visual anchor on page load.
- Trip metadata section: `.form-group` / `.form-row` pattern from dashboard modal. Fields: name, description, start date, end date, public/private checkbox.
- Destination accordion sections: each destination is a `.dest-section` block with:
  - Header (`.dest-section-header`): destination name + city/country + date range + collapse chevron + "Editar" + "Eliminar" buttons. Always expanded (no collapsed state required at v1).
  - Inside: Hotel subsection + Days list.
- Day rows: `.day-row` — color swatch + label + date + "Editar" / "Eliminar" buttons + activities list toggle.
- Activity rows: `.activity-row` — up/down reorder buttons (▲ ▼) + name + time (optional) + "Editar" / "Eliminar" buttons.
- Geocoder widget: `.geocoder-widget` — text input full-width + "Buscar lugar" button below or inline-right. Results list `.geocoder-results` shown inline below input, max 5 results, each a `<button>` row showing display name.

### Buttons

Reuse existing `.btn`, `.btn-primary`, `.btn-secondary` from dashboard.html inline styles.

New variant needed:
- `.btn-danger` — destructive actions (delete). Style: `background: transparent; border: 1px solid var(--color-destructive); color: var(--color-destructive)`. Hover: `background: var(--color-destructive); color: var(--bg-secondary)`.
- `.btn-icon` — up/down reorder controls. Style: 28×28px, `background: var(--bg-glass); border: 1px solid var(--border-color); color: var(--text-secondary)`. Content: ▲ or ▼ Unicode character at 14px. Hover: `background: var(--bg-glass-strong); color: var(--text-primary)`.

### Destructive confirmation modal

Reuse existing `.overlay` + `.modal` classes from dashboard.html verbatim. No new classes needed.

Modal content:
- `<h2>` — action name (e.g. "Eliminar destino")
- `<p>` — confirmation sentence (see Copywriting Contract)
- `.form-actions` row — "Cancelar" (`.btn-secondary`) + "Eliminar" (`.btn-danger`)

### Inline error display

Reuse existing `.error-msg` class (`color: var(--color-destructive); font-size: 14px; margin-top: 8px`). Placed immediately after the relevant form group, not at form bottom.

### Public/private toggle (SHARE-01)

Inline checkbox with label. Rendered inside the trip metadata form group:

```
<div class="form-group form-group--checkbox">
  <label class="checkbox-label">
    <input type="checkbox" id="trip-public" name="is_public">
    Hacer público
  </label>
</div>
```

Styles:
- `.form-group--checkbox` — `flex-direction: row; align-items: center; gap: 8px`.
- `.checkbox-label` — `font-size: 14px; font-weight: 400; color: var(--text-primary); cursor: pointer; display: flex; align-items: center; gap: 8px`.
- Native checkbox — `width: 16px; height: 16px; accent-color: var(--accent)`.
- No custom checkbox widget — native only.

## Interaction Contracts

### Geocoder (TRIP-07)

1. User types query into text input.
2. User clicks "Buscar lugar" button (or presses Enter).
3. Loading state: button shows "Buscando…" text, disabled, `opacity: 0.6`.
4. Results render in `.geocoder-results` list below input. Each result is a `<button>` with `display:block; width:100%; text-align:left; padding: 8px 12px; font-size:14px; border-bottom: 1px solid var(--border-color); background: var(--bg-secondary)`. Hover: `background: var(--accent-subtle)`.
5. User clicks a result — coordinates populate hidden lat/lng fields. Results list hides. Input shows selected display name. Text color stays `var(--text-primary)`.
6. No results: single `.geocoder-results` row reading "Sin resultados. Probá con otra búsqueda." (`var(--text-tertiary)`, 14px).
7. Error (network failure): `.error-msg` appears below `.geocoder-results`.

### Activity reorder (TRIP-06)

- ▲ button on first activity in a day: `disabled` attribute + `opacity: 0.35; cursor: default`.
- ▼ button on last activity in a day: `disabled` attribute + `opacity: 0.35; cursor: default`.
- On click: row animates up/down via `transition: transform 0.15s ease` before DOM reorder.
- After reorder: PATCH to backend. On error: revert DOM order + show `.error-msg` inline beneath activity row.

### Day color picker (TRIP-05)

- Rendered inside the day edit form (inside modal or inline, same `.form-group` pattern).
- 8 swatch buttons in a flex row, `gap: 8px`.
- Each swatch: `<button type="button" class="color-swatch" data-color="--marker-N" style="background: var(--marker-N)">` — 24×24px square, `border: 2px solid transparent; border-radius: 2px`.
- Selected: `border-color: var(--text-primary)` + `box-shadow: 0 0 0 2px var(--bg-secondary)` (ring gap).
- On hover: `transform: scale(1.15)`.
- Accessible: each swatch has `aria-label="Color N"` and `aria-pressed` reflecting selected state.

### Destructive confirmation (all delete actions)

1. User clicks "Eliminar" (`.btn-danger`).
2. `.overlay` becomes visible (remove `hidden`). Focus moves to modal.
3. User clicks "Cancelar" → overlay hidden, focus returns to trigger button.
4. User clicks "Eliminar" in modal → DELETE request sent. Button disabled + text "Eliminando…". On success: overlay hidden, item removed from DOM. On error: `.error-msg` shown inside modal.
5. Pressing Escape: same as Cancelar.

### Accordion sections (destinations)

- All sections expanded by default on page load (no collapsed state required at v1).
- Future: chevron toggle. For now, chevron icon present but non-interactive (static, pointing down).
