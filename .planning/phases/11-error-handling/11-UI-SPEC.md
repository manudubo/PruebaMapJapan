## Spacing Scale

Declared values for this component (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between toast message and close button |
| sm | 8px | — |
| md | 12px | Toast card vertical padding |
| lg | 16px | Toast card horizontal padding; container inset from viewport edge |
| xl | 24px | — |
| 2xl | 48px | — |
| 3xl | 64px | — |

**Toast card padding:** 12px top/bottom, 16px left/right (`padding: 12px 16px`).

**Toast container position:** 16px from viewport top, 16px from viewport right.

**Gap between stacked toasts:** 8px (vertical gap between cards in the container).

**Minimum toast width:** 280px. Maximum toast width: 360px. On mobile (viewport < 480px): full-width minus 32px (16px margin each side), max-width 100%.

Exceptions: close button touch target minimum 44px × 44px (accessibility requirement — the visual button is smaller; add negative margin or padding to reach 44px tap area without affecting layout).

## Color

This component is a component spec. The 60/30/10 page-level split is N/A.

### Toast card background, border, and text — per type

Each type uses the **subtle-tint + color-mix-border + full-color-text** pattern established by `.status-msg--*` (`main.css` lines 521–531). This is the correct interpretation of D-06 ("error uses `--jp-danger`"): the token governs the **text and border accent**, not a solid fill.

| Type | Background | Border | Text color |
|------|-----------|--------|------------|
| `error` | `var(--jp-danger-subtle)` | `color-mix(in srgb, var(--jp-danger) 35%, transparent)` | `var(--jp-danger)` |
| `success` | `var(--jp-success-subtle)` | `color-mix(in srgb, var(--jp-success) 35%, transparent)` | `var(--jp-success)` |
| `info` | `var(--jp-accent-subtle)` | `color-mix(in srgb, var(--jp-accent) 35%, transparent)` | `var(--jp-accent)` |

The `info` type has no existing analog in `.status-msg` but follows the same triadic pattern using `--jp-accent-subtle` (defined at `main.css` line 30/90).

### Close button (×)

| State | Color |
|-------|-------|
| Default | `var(--jp-text-secondary)` |
| Hover | `var(--jp-text)` |

### Elevation

**Decision:** use `--jp-shadow-lg` (not `--jp-shadow-md`). `--jp-shadow-md` is `none` in both light and dark themes (`main.css` lines 39, 97), giving no elevation. `--jp-shadow-lg` (`0 12px 40px rgba(0,0,0,0.12)` light / `0 12px 40px rgba(0,0,0,0.5)` dark) is the value the comparable `.modal` floating element uses. Toasts are floating elements and must read above page content, so `--jp-shadow-lg` is correct.

**Border-radius:** `var(--jp-radius)` which resolves to `0` — matches project minimalist aesthetic (CONTEXT.md "border-radius: 0").

## Copywriting Contract

All strings are locked (source: CONTEXT.md D-07 through D-14).

| Element | Copy | Type |
|---------|------|------|
| API error (all codes) | "Something went wrong. Please try again." | `error` |
| Unhandled rejection (all) | "An unexpected error occurred" | `error` |
| 401 session expired | "Session expired — redirecting to login" | `info` |
| Trip load failure (trip-edit.ts) | "Could not load trip — returning to dashboard" | `error` |
| Success (caller-defined) | e.g. "Trip created", "Trip deleted" — caller supplies exact text | `success` |

Note: the dash character in session expired and trip load failure messages is an em-dash (—), not a hyphen-minus.

Destructive actions in this phase: none that use a confirmation dialog. The toast-then-redirect pattern (1500ms delay) is the destructive handling for both the 401 redirect (D-10) and the trip-edit redirect (D-14) — no additional confirmation overlay.

## Component Specification

### HTML Structure

```html
<!-- Container (injected once into document.body on first showToast() call) -->
<div id="toast-container" role="region" aria-label="Notifications" aria-live="polite">

  <!-- Individual toast card -->
  <div class="toast toast--error" role="alert" aria-live="assertive">
    <span class="toast-msg">Something went wrong. Please try again.</span>
    <button class="toast-close" aria-label="Dismiss">×</button>
  </div>

  <div class="toast toast--success" role="alert" aria-live="polite">
    <span class="toast-msg">Trip created</span>
    <button class="toast-close" aria-label="Dismiss">×</button>
  </div>

</div>
```

**ARIA rules:**
- `error` toasts use `role="alert"` (implies `aria-live="assertive"`) — screen reader interrupts immediately.
- `success` and `info` toasts use `role="status"` (implies `aria-live="polite"`) — screen reader waits for idle.
- Container has `role="region"` with `aria-label="Notifications"` for landmark navigation.
- Do NOT move focus to the toast card on show — auto-dismissing elements must not steal keyboard focus.
- Close button `aria-label="Dismiss"` is mandatory (× alone has no accessible name).

### CSS Class Naming

| Class | Role |
|-------|------|
| `#toast-container` | Fixed-position container, top-right |
| `.toast` | Individual card — base styles |
| `.toast--error` | Error type modifier |
| `.toast--success` | Success type modifier |
| `.toast--info` | Info type modifier |
| `.toast-msg` | Message text span |
| `.toast-close` | × dismiss button |
| `.toast--exiting` | Applied by JS before removal to trigger fade-out |

### Animation

**Slide-in (on append):** toast slides in from the right.

```css
@keyframes toast-in {
  from { transform: translateX(calc(100% + 16px)); opacity: 0; }
  to   { transform: translateX(0);                  opacity: 1; }
}

.toast {
  animation: toast-in 0.2s ease;
}
```

**Fade-out (before removal):** JS adds `.toast--exiting`; after 200ms transition, element is removed from DOM.

```css
.toast--exiting {
  opacity: 0;
  transition: opacity 0.2s ease;
}
```

**Reduced motion:** when `prefers-reduced-motion: reduce` matches, disable slide-in and use opacity-only transitions.

```css
@media (prefers-reduced-motion: reduce) {
  .toast {
    animation: none;
  }
  .toast--exiting {
    transition: opacity 0.15s ease;
  }
}
```

### Behavior — Auto-dismiss

- All types: 4 seconds after append, JS adds `.toast--exiting`, waits 200ms (matches fade-out duration), then removes the element from DOM.
- If the user clicks × before the timer fires, clear the timer, add `.toast--exiting`, wait 200ms, remove.
- Stacking order: each new toast is appended at the top of the container (newest on top). Use `flex-direction: column-reverse` on the container OR prepend DOM nodes — decision left to implementer; visual result must be newest-on-top.

### Stacking — Newest on Top

Prepend each new toast card to `#toast-container` (i.e., `container.prepend(card)` not `container.append(card)`). This gives newest-on-top stacking without CSS column-reverse (simpler DOM order for screen readers).

## Interaction Contract — 401 Auto-Redirect

Sequence (D-10):
1. `client.ts request()` receives `response.status === 401`.
2. Call `showToast('Session expired — redirecting to login', 'info')` synchronously.
3. After `1500ms`, call `login('dashboard.html')`.
4. The toast will auto-dismiss after 4s, but the redirect happens first at 1.5s — this is intentional (user sees the message for 1.5s before navigation).

---

## Interaction Contract — trip-edit.ts redirect

Sequence (D-14):
1. Trip load fails in `trip-edit.ts` catch block.
2. Call `showToast('Could not load trip — returning to dashboard', 'error')`.
3. After `1500ms`, redirect to dashboard.

## Responsive Behavior

| Viewport | Behavior |
|----------|----------|
| >= 480px | Container: 360px wide, fixed top-right, 16px from edge |
| < 480px | Container: full-width minus 32px total margin (16px each side), max-width 100% of that |

On mobile, toasts stack full-width under the top-right position. The container `right: 16px; left: 16px; width: auto` replaces the fixed 360px width at < 480px.
