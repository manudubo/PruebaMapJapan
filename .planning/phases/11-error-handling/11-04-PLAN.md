<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| window unhandledrejection event → toast | Rejection reason crosses from async code into UI notification |
| trip-edit load failure → toast message | Error path crosses into UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-04-01 | Information Disclosure | installGlobalErrorHandler event handler | mitigate | Handler shows hardcoded string "An unexpected error occurred" (D-09) — rejection reason is never forwarded to toast message. event.preventDefault() suppresses console output. |
| T-11-04-02 | Information Disclosure | dashboard.ts getMyTrips catch | mitigate | showToast('Something went wrong. Please try again.', 'error') — no error details in message (D-07). |
| T-11-04-03 | Injection (XSS) | all showToast() calls in this plan | mitigate | All message strings are hardcoded literals (D-07, D-09). No user-supplied or API-response string is passed to showToast() in this plan. toast.ts uses .textContent anyway (Plan 11-01). |
| T-11-04-04 | Elevation of Privilege | trip-edit.ts redirect target | accept | `window.location.href = 'dashboard.html'` — hardcoded relative path, not user-controlled. No open-redirect vector. |
</threat_model>
