<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Email body HTML → FreeMarker render | Body HTML in .properties files passes through kcSanitize() before rendering — sanitizer removes unsafe HTML |
| Email rendered HTML → email client | HTML email is read-only for recipient; no user input flows back |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-08 | Tampering (XSS) | email/html/*.ftl body delegation | mitigate | Every html/*.ftl body call uses `kcSanitize(...)?no_esc` — kcSanitize() strips unsafe HTML (scripts, event handlers, javascript: hrefs) before FreeMarker renders. Do NOT remove kcSanitize() or ?no_esc. Verified by grep acceptance_criteria. |
| T-10-09 | Tampering | messages/*.properties HTML values | mitigate | Body HTML in .properties files must not contain script elements or JS event handlers. Values use only inline style attributes on block elements (p, a, td) — safe per kcSanitize() implementation. Verified by rg for script/javascript:/onXxx= in acceptance_criteria. |
| T-10-10 | Tampering | email/html/template.ftl inline styles | accept | Inline styles use literal color/font values (not user input); email clients render inline styles correctly; no external CSS loaded (email client compatibility requirement) |
| T-10-11 | Information Disclosure | Email body content | accept | Email body copy uses parameterized placeholders ({0}–{4}) substituted by KC — no PII beyond what KC already includes in base templates; consistent with KC base template design |
</threat_model>
