```hcl
  email_verified = true

    value     = var.trip_edit_test_user_password
    temporary = false
  }

```

IMPORTANT for INFRA-01: `import = true` means Terraform adopts the existing KC user without destroying it. `initial_password` on an imported user is cosmetic — the provider does not reset the password. Omit `first_name` and `last_name` intentionally — adding them would force-write over the existing user's profile state.

IMPORTANT for INFRA-02/INFRA-03: `first_name` and `last_name` are REQUIRED. Their absence triggers KC's "Update Profile" required-action prompt at first browser login (breaks E2E tests). The e2e_test_user analog sets them for this exact reason.

```hcl
    "http://localhost:5173/PruebaMapJapan/index.html",
```

All other attributes on the client block (access_type, pkce_code_challenge_method, web_origins = ["+"], full_scope_allowed) remain unchanged.

URI rationale (from RESEARCH.md enumeration of keycloak.ts callsites):
- `silent-check-sso.html` is required — used as `silentCheckSsoRedirectUri` on every page init
- `dashboard.html` and `profile.html` — login() fires from these pages
- `index.html` — logout redirects here; also needed for post-login redirect
- trip.html and trip-edit.html are intentionally excluded — login() does NOT fire from those pages
- `web_origins = ["+"]` is kept — derives allowed origins from redirect URIs (SEC-03 compliant after wildcard removal)

NOTE for future phases: If Phase 14/ERR-05 adds a 401 auto-redirect from trip-edit.html, add `http://localhost:5173/PruebaMapJapan/trip-edit.html` and its prod equivalent to this list.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HCL variables.tf → Terraform state | Password variable defaults (sensitive=true) flow into tfstate |
| Terraform state file | Contains sensitive outputs (worker_client_secret) and potentially password values |
| KC Admin REST API | Terraform provider authenticates with kc_admin_pass to manage realm resources |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02-01 | Information Disclosure | `variables.tf` password defaults (testuser_password = "Test1234!") | accept | These are test-only credentials for local dev KC; no production data at risk; defaults documented as matching existing hardcoded spec credential |
| T-12-02-02 | Information Disclosure | Terraform state file containing `worker_client_secret` output and variable values | mitigate | State file is already gitignored (terraform/keycloak/.gitignore or root .gitignore); all credential variables use `sensitive = true` which prevents them appearing in plan/apply console output; do not commit `.tfvars` files with real secrets |
| T-12-02-03 | Tampering | `import = true` on testuser — provider adopts existing user without validation | accept | Intent is deliberate: adopt pre-existing manually-created user; password preserved in KC, not overwritten; passkeys preserved; low risk in local dev context |
| T-12-02-04 | Elevation of Privilege | SEC-03 wildcard removal — strict URIs prevent redirect_uri injection attacks | mitigate | Replacing `http://localhost:5173/*` with 4 explicit paths + `silent-check-sso.html`; web_origins=["+"] bounded by explicit URI list after wildcard removal; future login callsites must add URIs explicitly |
